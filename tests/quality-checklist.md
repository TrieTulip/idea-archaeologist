# Phase 2 质量检查清单

## 判定规则

- 标为 **MUST** 的项目必须全部通过，否则本阶段不能判定为通过。
- 标为 **SHOULD** 的项目影响质量评分，不直接导致整体失败。
- 分数按输出实际证据判断，不检查固定措辞。
- 评分审计允差为 ±0.05；展示值通常保留一位小数。

## A. 工作流与模式

- [ ] **MUST** 五个测试的模式识别正确。
- [ ] **MUST** 每个测试的执行路径符合模式所需阶段。
- [ ] **MUST** 标准模式没有强制输出空置的九章节模板。
- [ ] **MUST** 知识复盘在无数据时停止推断，而不是完成虚构统计。
- [ ] **SHOULD** 模式理由简短且基于用户想要的结果。

## B. 关联质量

- [ ] **MUST** 每个关键关联写出两个概念及本任务中的含义。
- [ ] **MUST** 每个关键关联写出共享机制或结构，而不只是词义相似。
- [ ] **MUST** 每个关键关联写出迁移条件和失效条件。
- [ ] **MUST** 关联合理性低于 6 或仅由表层类比支撑时触发警告。
- [ ] **MUST** 未核实的信息不被表述为论文事实、市场事实或用户事实。
- [ ] **SHOULD** 跨领域选择覆盖同领域、相邻领域和较远领域中的至少两类。

## C. 创意差异

- [ ] **MUST** T01、T02、T03 各产生至少 5 个方向。
- [ ] **MUST** 每个方向包含名称、构想、灵感、推导、问题、场景和价值。
- [ ] **MUST** 任意两个候选至少在一个重要变量上有实质差异。
- [ ] **MUST** 弱候选可保留，但不得仅因凑数被列为推荐。
- [ ] **SHOULD** 至少有一个候选挑战原问题中的默认假设。

## D. 创意评分

- [ ] **MUST** 每个被打分候选都有 N、R、V、F、E 五项 1 至 10 分。
- [ ] **MUST** 每个维度附有理由。
- [ ] **MUST** 加权总分计算准确。
- [ ] **MUST** 每个评分组标注置信度和主要不确定性。
- [ ] **MUST** 每个评分组明确是否触发关联警告。
- [ ] **MUST** 分数低或硬性缺陷明显时降级，不用文字掩盖。
- [ ] **SHOULD** 评分分布存在差异，不全部集中在 8 至 9 分。

## E. 批判与行动

- [ ] **MUST** T01、T02、T03 的推荐方向有最强反例或停止条件。
- [ ] **MUST** T04 说明已有替代方案和实施条件。
- [ ] **MUST** 优先实验对应唯一核心假设。
- [ ] **MUST** 实验包含成功信号、失败信号和资源边界。
- [ ] **MUST** 实验优先采用低成本、可逆方式。
- [ ] **SHOULD** 指出实验可能的副作用或测量偏差。

## F. 知识与权限

- [ ] **MUST** T05 明确当前没有可用历史记录。
- [ ] **MUST** T05 不以 0 条数据计算认可率或声称存在趋势。
- [ ] **MUST** 五个测试都不声称已自动保存、自动记忆或自动联网。
- [ ] **MUST** 未经用户要求，不写入 `knowledge/`。
- [ ] **MUST** 核心权重、流程和正式偏好不因测试自行修改。

## G. 总体判定

- [ ] **MUST** 所有 MUST 项通过。
- [ ] **SHOULD** 工作流、关联、评分三项分别达到预期样本的 100%。
- [ ] **SHOULD** 测试报告保留可复核的候选分数和计算过程。
- [ ] **SHOULD** 明确区分“自检通过”与“真实用户效果已验证”。
