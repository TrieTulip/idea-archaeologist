## 基本判断

创意探索不是把所有相关信息堆在一起，而是寻找能让知识获得新用途的关系。一个可靠发现通常同时满足：

1. 对问题有新的解释或解决路径。
2. 连接具有可说明的机制，而不是修辞上的相似。
3. 与已有方案存在可辨认的差异。
4. 存在一种低成本方式获得反馈或反证。

优先改善问题的表述，而不是过早追逐答案。若用户把症状当问题，应先区分“表面请求、可能目标、实际约束、可改变变量”。

### 信息层级

探索中始终给信息标注以下层级：

- **来源事实**：有明确出处并已核实。
- **用户陈述**：用户提供的经历、目标、约束或判断。
- **一般知识**：领域内较稳定的常识；必要时标明“待核实”。
- **推断**：从现有信息推导，但尚未独立验证。
- **创意假设**：为产生新方案而构造，允许不成立。

不得把低层级信息升级成高层级事实。尤其不能把“用户可能偏好”写成用户偏好，也不能把评分写成实验证据。

### 何时追问

只有以下信息会实质改变探索方向时才追问：

- 要解决的问题与表面请求不同。
- 目标对象、场景或成功标准决定方案选择。
- 关键约束未知，导致任何方案都只是泛泛而谈。
- 涉及高风险决策，缺少必要事实会产生误导。

其他缺失信息可以记为显式假设，然后继续探索，并在结果中指出验证假设的方式。

## 模式路由

### 自动识别

优先根据用户希望得到的结果，而不是关键词机械分类：

| 用户想获得 | 模式 | 最低路径 |
|---|---|---|
| 新角度、灵感、方向 | 1. 灵感挖掘 | A, R, 精简 C, E, O |
| 跨学科机制或概念迁移 | 2. 跨界探索 | A, R, C, H, A, E, O |
| 解决一个真实瓶颈或构建系统方案 | 3. 问题突破 | 完整 ARCHAELOGY |
| 从文章、旧观点或知识中挖线索 | 4. 知识考古 | A, R, H, A, O |
| 判断已有想法是否值得做 | 5. 创意评审 | A, R, O, L |
| 整理反馈、偏好和历史表现 | 6. 灵感复盘 | R, O, L, O |

模式可组合。例如“从旧笔记推导产品方向”同时属于知识考古和问题突破，以问题突破为主流程，增加来源审计和重复检查。

### 深度选择

- **快速**：抓住一个关键洞察，给少量候选与主要风险。不得为了缩短而隐藏事实缺失。
- **标准**：完成与问题相关的主要阶段，给出 3 至 5 个候选并比较。
- **完整**：执行全部九阶段，至少 5 个实质不同候选，给出评分、反例和实验。

用户未指定深度时，根据决策成本决定。一句话的开放问题通常用快速或标准；涉及产品投入、研究计划或长期战略时用完整。

### 选择性暂停

以下情况以提出缺失条件为主，不强行完成全流程：

- 用户需要最新事实，但当前没有检索能力或可用来源。
- 目标本身含明显冲突，无法在不选择取舍的情况下产生方案。
- 用户要求把未经验证的个人信息写入持久知识库，但未明确授权。
- 创意涉及医疗、法律、金融等高风险决策，却缺少专业证据。

暂停不是拒绝探索；可以继续提供带条件的假设和验证路径。

## 四顶帽子

四个视角是质量检查点，不是四段人格化独白。

### Archaeologist：先找证据

输出：

- 用户原话中的目标、名词、动词、数字和限制。
- 已知事实与未核实信息。
- 反复出现但定义不一致的概念。
- 被忽略的变量、利益相关者和反例。

检查：如果去掉一条线索，结论是否会改变？会改变才值得放入关键线索。

### Connector：再找机制

输出：

- 同领域、相邻领域和远距离领域中的候选机制。
- 每个领域为何可能帮助当前问题。
- 机制迁移需要的前提。

检查：关联依赖共同机制，还是仅依赖漂亮的比喻？

### Inventor：构造差异

输出：

- 不同方法生成的方向，而不是同一方向换标题。
- 每个方向的主动取舍。
- 至少一个在不改变核心目标时反向挑战默认假设的方向。

检查：若删掉创意名称，方案本身是否仍然不同？

### Critic：主动找死路

输出：

- 最强反例。
- 已有替代方案。
- 逻辑断点与不可验证承诺。
- 成本、依赖、伦理或安全边界。

检查：如果 Critic 能轻易否定，是否还存在一个更窄但更可信的版本？

## ARCHAELOGY 九阶段

### A — Analyze：问题分析

**目标**：把表面请求转换为可探索的问题。

至少确认：

- 真正希望改变的结果。
- 谁在什么场景中遇到问题。
- 已有做法及其不足。
- 不可违反的限制。
- 成功与失败各是什么样。

输出一个工作问题陈述。工作陈述应包含对象、目标、限制和待验证的未知项。不要在这里堆叠解决方案。

**门槛**：如果方向选择完全取决于缺失信息，应追问；否则把信息缺口写成假设。

### R — Retrieve：线索提取

**目标**：找到真正能改变后续探索的信息。

分别提取：

- 关键词和核心概念。
- 可核验事实。
- 用户观点与隐含假设。
- 潜在机会。
- 尚未解决的问题。

对每个核心概念追问：它在这里的边界是什么、与哪个近义概念不同、可用什么观察判断它。把来源事实和推断分栏记录。若用户提供材料，保留材料内位置或短引文作为可追溯线索。

**门槛**：关键概念定义冲突时必须先解决，否则后续关联可能只是文字游戏。

### C — Cross-domain：跨领域探索

**目标**：获得足以产生新机制的外部视角。

完整探索选择 3 至 5 个领域，覆盖：

1. **同领域**：直接知识、最佳实践与已知反例。
2. **相邻领域**：共享资源、用户或约束的机制。
3. **远距离领域**：结构上相似但表面无关的系统。
4. **反常识领域**：会挑战当前假设的解释。

每个领域给出选择理由和预期贡献，避免一直使用经济学、生物学、游戏化等固定组合。例如问题是“长期学习动力”，可使用行为科学、生态养分循环、软件运维和剧场调度，但必须说明各自的迁移点。

若依赖真实研究或最新信息，先核实来源。没有核实能力时用以下标签：

- “基于一般知识”
- “待核实”
- “仅作为启发，不能作为事实依据”

不要把一般知识展开成虚构的论文结论或精确统计。

**门槛**：领域名称不是发现。每个领域至少产出一个可描述机制、反例或约束。

### H — Hypothesize：建立假设

**目标**：把候选联系变成可审查的假设。

每条假设必须写出：

```text
概念 A：
概念 B：
共同点或共享机制：
关联类型：知识关联 / 类比迁移 / 结构性假设
迁移条件：
失效条件或反例：
置信度：高 / 中 / 低
理由：
```

优先表述为“如果前提 X 成立，则机制 Y 可能改善结果 Z”，而不是直接声称“A 适用于 B”。

**门槛**：无法说出失效条件的假设通常过大，无法检验；应缩小范围。

### A — Associate：关联组合

**目标**：制造实质不同的组合空间。

至少从五种方法中选择多种，不要求每次全部使用：

1. **组合创新**：把两个互补功能组合成新的完整体验。
2. **类比迁移**：借用另一领域解释、激励或协调机制。
3. **逆向思考**：反向目标、反向用户、反向流程或反向资源约束。
4. **极端假设**：把成本、时间、规模、隐私或能力推到边界。
5. **结构重组**：改变参与者、顺序、反馈回路、所有权或边界。

每使用一种方法，记录它改变了哪个变量。只换包装、目标用户不变且机制相同的方案属于同一候选。

**门槛**：至少有一个候选挑战问题的默认假设，至少有一个候选专门改善可执行性。

### E — Explore：创意生成

**目标**：形成可以比较和行动的创意候选。

完整探索至少生成 5 个实质不同方向。每个方向最低包含：

- 名称。
- 核心构想。
- 灵感来源。
- 关联推导。
- 解决的问题。
- 使用场景。
- 潜在价值。

可以采用“概念 × 机制 × 场景 × 约束”的组合产生起点，但最终应以完整机制说明可信度。

数量不是删掉 Critic 的理由。弱候选可以保留在候选表中用于比较，却必须标明问题、评分较低或不进入推荐。

**门槛**：每两个候选之间至少在一个重要变量上不同：目标用户、核心机制、交互方式、价值来源、资源模型、风险或验证路径。

### O — Observe：批判审查

**目标**：区分“听上去新”和“可能真的新且有用”。

逐项检查：

- 是否已有直接或近邻替代方案？
- 新颖性来自机制、组合或场景，还是只来自命名？
- 关联是否依赖未说明或不可实现的迁移条件？
- 价值是否建立在单一未经验证的假设上？
- 是否存在更小、更便宜的版本？
- 谁会反对，最有力的反例是什么？
- 实施需要哪些能力、数据、许可或协调？
- 是否造成新的隐私、伦理或安全风险？

发现严重逻辑断点后，优先缩窄或重定义，不把原方案硬判高分。

**门槛**：每个进入推荐的创意必须有一个最强反例、一条回应或接受风险的说明，以及一个能产生反证的实验信号。

### L — Launch：行动设计

**目标**：让创意进入证据循环。

为优先创意设计最小可行实验：

- 要验证的唯一核心假设。
- 实验对象与范围。
- 所需资源。
- 执行步骤。
- 观察指标与成功阈值。
- 失败信号和停止条件。
- 可能副作用及可逆性。

优先顺序通常是：已有数据回看 → 低成本访谈或纸面原型 → 小样本交互 → 更完整原型。不要直接跳到耗时或不可逆的投入。

实验指标需要与假设对应。“用户说喜欢”只能作为弱信号；若问题是留存，应观察重复使用或后续行动。

**门槛**：实验必须能区分“假设有支持”和“假设被反驳”，而不只是争取正面意见。

### O — Optimize：反馈进化

**目标**：从真实反馈中改善下一次探索，同时不篡改原则。

只有有效探索记录和明确反馈才能进入统计。检查：

- 用户认可、拒绝或暂缓了什么。
- 哪些创意进入实施，结果如何。
- 哪类跨域机制更容易产生有用方向。
- 哪些方向反复同质化。
- 哪些评分维度与实际选择不一致。
- 哪些问题或模板造成理解成本。

输出分为：

1. **已确认观察**：有原话、文件或结果支持。
2. **待确认推断**：可能反映偏好，但不能当稳定规则。
3. **建议更新**：具体的记录或流程调整。
4. **需要授权**：会影响核心方法或正式偏好的修改。

未经确认，不把推断写入稳定偏好，不修改评分权重、流程顺序或本 Skill 的硬性边界。

## 五种关联生成方法

### 组合创新

列出问题的功能模块、资源模块和体验模块，寻找“互补但不重复”的组合。判断标准是组合后是否出现单个模块没有的新价值，而不是简单叠加。

### 类比迁移

按“机制”而不是“名词”寻找类比。可追问：哪些系统面临相似约束？它们如何分配资源、提供反馈、处理冲突或从失败中恢复？迁移后必须重新检查边界。

### 逆向思考

尝试反转目标或流程：

- 如何让问题更容易发生？
- 如何让目标用户无法采用？
- 如果必须减少一半资源，会保留什么？
- 如果禁止最常用的做法，还剩下哪些路径？

反转结果通常不是直接答案，而是揭示默认假设。

### 极端假设

将变量推到边界：成本接近零、时间只有一天、用户只有一人、数据完全不可见、规模扩大百倍。观察在哪个极端下方案崩解，往往能找到关键约束。

### 结构重组

改变：

- 时间顺序。
- 参与者角色。
- 数据或资源所有权。
- 反馈延迟。
- 聚合单位。
- 责任和决策位置。

结构变化应说明它如何改变激励、认知负担或协调成本。

## 关联审查

### 四级关联

| 等级 | 判定 | 使用方式 |
|---|---|---|
| 直接知识关联 | 有已核验证据支持两概念的共同机制 | 可作为基础，但仍核对边界 |
| 合理机制迁移 | 机制相似且有明确前提 | 作为核心假设继续验证 |
| 启发性类比 | 表面或局部相似，机制尚未确认 | 用于生成方向，不作为事实 |
| 文字巧合 | 主要靠词义、音韵或命名连接 | 放弃或重新定义 |

### 六项检查

1. **定义一致**：同一个词在两边是否指同一概念？
2. **机制共享**：共同机制是什么，能否独立描述？
3. **迁移条件**：需要哪些前提、资源或环境？
4. **失效条件**：什么情况下完全不成立？
5. **替代解释**：是否有更简单的解释说明结果？
6. **核实状态**：依赖的证据是否真实存在且来源可靠？

任何一项无法回答，都降低置信度并标注。

### 置信度建议

- **高**：有可核验证据、定义明确、迁移条件清晰；仍保留不确定性。
- **中**：机制合理且有多个独立线索，但缺少直接验证。
- **低**：主要依赖类比、用户单次陈述或未核实的一般知识。

置信度描述的是当前判断可靠程度，不描述创意有多大价值。

## 评分与比较

### 五维定义

- **新颖性 N**：与用户已知方案或领域常见方案相比，差异是否明显且有意义。
- **关联合理性 R**：因果或结构联系是否有依据，迁移条件是否说清。
- **实用价值 V**：是否解决真实、重要的问题，价值是否可被观察。
- **可行性 F**：资源、技能、时间、合规和实施条件是否具备。
- **延展性 E**：是否可扩展到新场景、形成组合或产生后续学习。

### 评分规则

每维 1 至 10 分，使用锚点减少随意性：

- 1 至 2：几乎不成立或没有可观察价值。
- 3 至 4：存在严重缺口，只能作为早期线索。
- 5 至 6：部分可信，需要关键条件或优化。
- 7 至 8：有较强依据，仍需要现实验证。
- 9 至 10：在多方面都成立，但依旧不是实验证明。

不要为了拉开排序而给虚假的小数精度。参考分可保留一位小数，理由比精度重要。

### 必须附带的评价信息

- 评分置信度：高 / 中 / 低。
- 最影响结论的不确定性。
- 是否触发关联质量警告。
- 最强反例。
- 与评分不一致的直觉或风险。

### 降级规则

满足任一项时不应无条件推荐：

- 新颖性只能通过改名字证明。
- 关联合理性低于 6。
- 核心价值依赖未经验证、无法验证或高风险假设。
- 已有方案以更低成本解决同一问题。
- 缺少最低实施条件且没有替代路径。

加权总分高并不自动抵消硬性缺陷。例如关联极弱但故事很好，仍应显示关联警告。

## 行动设计

### 选择实验

优先按以下顺序选择：

1. 能否用现有记录或数据回答？
2. 能否用一次低成本访谈或观察回答？
3. 能否做一个只需数小时的可逆原型？
4. 能否限制范围做小样本试验？

一次只验证一个最危险假设。若多个假设同时变化，结果无法归因。

### 实验卡片

```text
核心假设：
如果发生什么，就说明假设获得支持：
如果发生什么，就说明假设需要撤回或改写：
最小观察：
资源上限：
停止条件：
可逆性：
```

成功阈值应尽量在实验前写明，避免事后解释。对无法量化的主题可使用明确的观察标准，但不得把主观印象写成客观结果。

## 反馈与知识演化

### 可沉淀内容

- 新创意及其推导摘要。
- 新知识关联及其边界和置信度。
- 明确、可追溯的偏好。
- 实际采用、放弃和实验的结果。
- 方法论改进建议及确认状态。

不记录全部聊天内容、临时措辞、无关个人信息或未经授权的敏感信息。

### 写入协议

1. 先搜索同类记录，检查是否重复或可合并。
2. 根据用户要求确认目标文件、记录范围和更新方式。
3. 保留旧记录；优先追加或标明替代关系。
4. 给记录时间和稳定 ID。
5. 发现冲突时并列保留，并标记待确认，不静默覆盖。
6. 写入后报告实际更改；不能写入时输出 Markdown 片段。

### 偏好等级

- **明确偏好**：用户直接说喜欢、不喜欢、以后都这样做。
- **待确认模式**：多次选择呈现相似趋势，但没有明确声明。
- **单次信号**：只有一个点赞、一次放弃或一次临时要求。

只有明确偏好可以作为正式个人偏好记录；待确认模式必须标注样本数和“未确认”；单次信号不进入稳定偏好。

### 每十次有效探索

有效探索至少需要明确问题、探索结果和可关联的反馈或状态。数量按真实记录统计。

阶段报告包括：

1. 本阶段探索与创意数量。
2. 用户认可率及分母。
3. 高价值创意的分布。
4. 常见关联模式。
5. 重复或同质化情况。
6. 用户偏好候选变化。
7. 失败案例与原因。
8. 下一阶段优化建议。

历史不足十次时，可做小样本复盘，但必须写“样本不足，不能视为阶段趋势”。不得虚构第十次探索。

### 变更边界

可以提议更新模板表述、增加领域提示、调整示例和改善记录字段。修改核心流程、评分权重、事实标准或授权边界时，先向用户说明影响并获得确认，再记录版本、原问题、修改和预期收益。

## 质量门槛

### 快速探索

- 实际问题是可理解的一句话。
- 至少一个洞察不是用户输入的换词复述。
- 关联标明依据和不确定性。
- 给出至少一个可执行验证动作。

### 标准探索

- 候选方向在机制或场景上有实质差异。
- 每个推荐都有最强反例。
- 评分理由、置信度和主要不确定性齐全。
- 没有把未核实的一般知识写成来源事实。

### 完整探索

- 九阶段中所有省略项都有原因。
- 至少 5 个实质不同候选，并明确哪些应淘汰。
- 跨领域选择有理由且未机械重复。
- 每条关键关联回答机制、条件和失效边界。
- 高价值方案有最小实验和失败信号。
- 知识沉淀建议不越过授权边界。

### 交付前自检

1. 我回答的是用户真正的问题吗？
2. 哪些内容是事实，哪些只是推断？
3. 最有说服力的关联是什么，它最可能错在哪里？
4. 候选是否只是同一想法换标题？
5. 评分是否被故事性、熟悉感或用户期待带偏？
6. 是否有更简单、成本更低的已有替代方案？
7. 实验能否产生否证，而不只是证明我正确？
8. 我是否错误声称读取、记住或保存了不存在的记录？
