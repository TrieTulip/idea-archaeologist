# Phase 3 知识进化测试用例

## 测试环境

- 日期：2026-11-01。
- 正式知识库：使用 `knowledge/` 当前真实状态。
- 测试夹具：`tests/fixtures/phase3/`。
- 测试数据与正式知识库物理隔离。
- 验证器只读，不修改任何知识文件。

## TEST P3-01：历史记录读取

- **目标**：验证系统能读取已有创意、关联、反馈和版本，并保持引用可追溯。
- **输入**：`fixtures/phase3/base`。
- **预期**：识别 2 条创意、1 条关联、1 条反馈、1 条版本。
- **必须检查**：反馈关联到存在的创意；字段完整；没有把测试数据写入正式知识库。

## TEST P3-02：反馈更新与偏好确认

- **前置状态**：只有一条“单次信号”，不能形成稳定偏好。
- **输入事件**：用户明确表示喜欢决策证据地图方向，以后优先少而精验证，并授权更新。
- **预期**：新增反馈事件；保留旧反馈；创建有反馈依据的明确偏好；创意状态变为“实验中”。
- **禁止行为**：覆盖旧反馈；从单次信号直接推断稳定偏好；无授权写入。
- **负向子用例**：`fixtures/phase3/unauthorized` 中的活动偏好依赖“未授权”反馈，验证器必须拒绝。

## TEST P3-03：重复检测与合并

- **负向输入**：两个创意具有相同去重键和近似标题。
- **预期**：验证器拒绝重复键，并给出两个记录 ID。
- **正向修复**：不新增“决策证据导航”，把相同机制候选合并到已有“决策证据地图”，追加合并记录。
- **禁止行为**：只按名称相似自动合并不同机制；生成重复创意记录。

## TEST P3-04：版本迭代

- **前置版本**：0.2.0 已应用。
- **新事务**：用户发起 Phase 3，实现知识进化协议与验证器。
- **预期**：追加 0.3.0，保留 0.2.0；状态为“已应用”，包含用户确认和实际修改。
- **必须检查**：Changelog 与知识版本一致；没有静默改写旧版本。

## 通过标准

- 验证器在 base、after 和正式 `knowledge/` 上通过。
- duplicate 夹具必须失败，且错误包含重复键和两个 ID。
- 正式知识库只包含初始骨架与真实的 0.3.0 迭代记录。
- 测试夹具不进入正式知识资产。
- 反馈、偏好和版本引用均存在。
