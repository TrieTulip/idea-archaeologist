# 知识索引、去重与进化协议

只在读取、更新、合并或复盘知识资产时加载。知识库不是自动记忆；只有实际读写后，才能声称完成。

## 目录

```text
knowledge/
├── index.md
├── ideas/
│   └── IA-YYYYMMDD-XX.md
├── connections/
│   └── CN-YYYYMMDD-XX.md
├── preferences.md
└── evolution.md
```

`index.md` 保存关键词、主题、摘要和详情路径；详细机制、来源与版本放入独立文件。先读索引，再读取命中记录。

## 选择性检索

1. 从请求提取 2–6 个关键词和问题机制。
2. 查 `index.md` 的主题、关键词和摘要。
3. 只读取相关命中；没有命中时不要伪造历史。
4. 找到近似记录时，检查去重键、目标问题和核心机制。
5. 复盘必须统计实际记录，不把测试夹具当用户历史。

## 索引记录

```markdown
## IA-YYYYMMDD-XX — 简短名称

- **类型**：创意
- **详情路径**：ideas/IA-YYYYMMDD-XX.md
- **关键词**：关键词1、关键词2
- **摘要**：一句机制摘要
```

关联使用 `CN` ID、类型“关联”和 `connections/` 路径。索引不重复完整推导和评分。

## 创意详情

必填：

- 日期、主题、创意名称、核心构想。
- 来源、推导逻辑、评分。
- 当前状态、去重键。
- 当前版本、版本历史。

版本历史每次只追加一行：版本、日期、变更依据、变更摘要。旧版本不得静默覆盖。

## 关联详情

必填：

- 日期、概念 A、概念 B。
- 共同原理、关联类型。
- 应用场景、适用边界、置信度。
- 去重键、当前版本、版本历史。

## 反馈与偏好

反馈存放在 `preferences.md` 的“反馈事件”区，必填：

- 日期、关联创意或“不适用”。
- 原始反馈、偏好级别、授权状态。
- 状态变更、重复检查。

偏好级别：

| 级别 | 可做 | 不可做 |
|---|---|---|
| 单次信号 | 记录原始反馈 | 推断稳定偏好 |
| 待确认模式 | 标注样本数 | 当作正式规则 |
| 明确偏好 | 在授权后建立偏好 | 扩展到未说过领域 |

活动 `PREF` 必须有真实 `FB` 依据、用户授权和确认状态。

## 写入事务

1. 确认用户明确要求保存、更新、合并或升级。
2. 读取 `index.md` 和命中的详情/反馈/版本。
3. 做 ID、去重键、标题和语义重复检查。
4. 只准备当前事务需要的最小变更。
5. 追加版本历史；保留旧内容。
6. 建立反馈→创意、偏好→反馈等引用。
7. 运行 `python scripts/validate.py knowledge`。
8. 报告实际新增、更新、合并、拒绝和未写入内容。

无法写入时，输出完整可合并 Markdown，并标记“尚未保存”。

## 重复检测

从强到弱：

1. **ID**：相同必须拒绝新增。
2. **去重键**：相同视为同一记录，更新原记录或建立版本。
3. **标题与结构**：规范化标题相同通常重复；近标题只警告。
4. **语义**：目标问题和核心机制相同通常合并；只换名称不产生新记录。

事实、偏好或状态冲突时并列保留依据并标记待确认，不静默覆盖。

## 变化与版本

- Patch：措辞、示例、兼容修正。
- Minor：新增模式、字段、模板或验证能力。
- Major：改变核心方法、评分权重、默认权限或事实边界。

`evolution.md` 的每条 `EV` 记录必须包含版本、日期、原有问题、优化建议、具体修改、预期收益、用户确认状态、应用状态和实际修改。

“已应用”必须有用户直接要求或明确确认；测试模拟不能冒充用户批准。

## 阶段复盘

只有真实有效探索和关联反馈进入统计。累计 10 次后才建议阶段趋势；不足时写实际样本数。

报告可包含：

- 探索和候选数量。
- 有明确评价的认可率及分母。
- 高价值候选分布。
- 常见关联模式和警告。
- 重复问题。
- 已确认偏好、待确认模式和单次信号。
- 低质量输出与失败原因。
- 下一阶段优化建议及其授权状态。

不根据小样本补造趋势，不把主观评分当实验结果。
