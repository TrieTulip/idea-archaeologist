# 跨领域推理与创意生成

只在需要寻找机制迁移、生成候选或检查差异时加载。

## 关联推导模型

对每个重要关联依次检查：

1. **定义**：两边是否在讲同一个概念、同一尺度、同一对象？
2. **机制**：共同点是因果、反馈、约束、资源分配、结构还是只是词义？
3. **迁移**：从来源领域具体借用什么机制，不是借用它听起来像什么。
4. **条件**：迁移需要哪些资源、参与者、时间、数据或许可？
5. **反例**：在什么情况下机制失效或产生相反结果？
6. **价值**：组合后出现了什么单个领域没有的新解释或新行动？

关联等级：

| 等级 | 使用方式 |
|---|---|
| 直接知识关联 | 有可核验证据支持共同机制，仍检查边界 |
| 合理机制迁移 | 条件明确，可生成假设并验证 |
| 启发性类比 | 只用于开拓方向，不作为事实结论 |
| 文字巧合 | 放弃或重新定义 |

## 五种生成方法

### 组合创新

列出功能、资源和体验模块，寻找互补而不重复的组合。判断组合是否产生新的反馈回路、服务流程或价值来源。

变量变化：组件之间的关系。

### 类比迁移

找面对相似约束的系统，迁移其资源分配、反馈、协调或失败恢复机制。写出迁移条件和失效边界。

变量变化：机制来源。

### 逆向思考

反转目标、用户、流程或资源：

- 怎样让问题更容易发生？
- 怎样让目标用户无法采用？
- 资源减半时保留什么？
- 禁止默认做法后还剩下什么路径？

变量变化：默认假设。

### 极端假设

把成本、时间、规模、隐私、能力或数据推到边界，观察方案在哪一点崩解。

变量变化：约束尺度。

### 结构重组

改变时间顺序、参与者角色、反馈延迟、聚合单位、数据所有权、责任位置或资源模型。

变量变化：系统结构。

## 候选差异检查

两个候选只要符合以下任一情况，就检查是否应合并：

- 目标问题相同。
- 核心机制相同。
- 目标用户和场景相同。
- 价值来源和资源模型相同。
- 只是名称、比喻或界面不同。

优先保留：

1. 能挑战原有假设的方向。
2. 能用更低成本获得证据的方向。
3. 关联机制清楚但尚未被常见方案覆盖的方向。

## 来源层级

- **已核实事实**：有明确、可追溯来源。
- **用户陈述**：用户提供但尚未独立验证。
- **一般知识**：领域常识；必要时标“待核实”。
- **推断**：从现有信息推导，尚未独立验证。
- **创意假设**：为生成方案构造，允许被反例推翻。

不检索不等于不能推理；但必须让读者知道哪些结论仍依赖外部核实。
